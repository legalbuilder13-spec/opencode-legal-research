## Result

Codex app-server is the candidate default, subject to its upstream experimental support status and the clean-profile tests below.

## Production integration plan

1. Add an execution-adapter boundary in `packages/opencode` rather than treating app-server as an ordinary HTTP model provider.
2. Persist `{session_id, codex_thread_id, codex_version, protocol_hash}` and enforce one active turn per mapping.
3. Translate deltas, tool/status items, errors, and terminal states idempotently into OpenCode session parts.
4. Expose managed ChatGPT account state and rate limits in settings without exposing tokens.
5. Package a reviewed Codex binary or enforce a compatible installed version and verify the manifest before the first turn.
6. Run the open clean-profile cases in an isolated Codex home, then update the ADR before production use.

## Decision

Conditionally select Codex app-server. The no-API-key requirement is feasible, but production release remains blocked on upstream maturity acceptance, clean-profile authentication coverage, and host session integration.
